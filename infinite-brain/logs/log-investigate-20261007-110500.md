The question was whether sharding is a no-op because `to_executor_set()` is `stakers.clone()`.
It is not a no-op — but the reason it isn't, and what that exposes, are better than the answer.

Separating the effects: sharding **does** cut per-transaction execution work by roughly
`1/shard_count`, which needs no disjoint membership. It does **not** cut links (selection is
per-transaction from everyone, so a node needs the union of subsets), and it does not touch
the tail — executor→finalizer and finalizer→committer still fan out to whole role buckets.

The interesting part was checking whether the tail would *break* under sharding. A global
quorum denominator should make `shard_count > 1` stall loudly: a shard can never produce
two-thirds of the whole validator set. It does not stall. `reconcile_signatures` sums the
stake of signatures that arrived and uses **that** as 100%; if the threshold is never met it
takes `candidates.first()` and carries on. There is no comparison between the voters and the
assigned executors anywhere in the path.

At `shard_count: 1` this is accidentally correct — selection returns every positive-stake
executor (`leader.rs:181-194`), everyone is preloaded, everyone signs, so arrivals equal the
validator set. The check is right by delivery completeness, not by construction. Which is
exactly why it matters that per-key sends are uncounted (Phase 0 item 2): a dropped send
shrinks the denominator along with it, silently, with no metric. Items 2 and 3 turned out to
be one problem wearing two hats.

Checked the contrast case rather than asserting it: the committer's block-confirmation gate
(`quoruming.rs:55-75`) divides by a **declared** `total_stake()` from its own stake-set cache.
So the protocol has one real gate and one decorative one, and any fault-tolerance claim needs
to say which it means. Also corrected a claim from earlier today: the composite's literal
`66.6` *is* used by `reconcile_signatures` (so `env_data.quorum_percentage` really is ignored
on that path), while the literal `4` feeds `total_voters`, whose only consumer `check_quorum`
has no production caller — inert, not dangerous. Conflating them was wrong.

Consequence for the roadmap: "shard-scoped quorum denominators" was the wrong phrase. There is
no global denominator to scope; there is an undefined one. Phase 7's first consensus job is to
make the denominator a set the block *names* and the receiver *verifies*. Phase 0's minimal
version: pass the assigned set into reconciliation and make a shortfall distinguishable —
reject, or at minimum count it — since the declared numbers are already sitting in the block
builder unused.

Two committee shapes now written into Phase 7 as the answer the gate demands: rotating disjoint
committees (deterministic from epoch seed, so still recomputable, degree ≈ N/shard_count, needs
a committee-size floor) versus token-scoped committees (follows the state partition the lattice
already has, but concentrates risk on high-value tokens and needs `chain_id` to become a real
read field — a lockstep wire change). The salt decision the user is holding is independent of
this choice, which is worth saying out loud before they answer it.

The question was where sharding belongs in the production roadmap. The honest answer
turned out to be "mostly not there", and the reason is worth keeping.

The two defects I found while scoping sharding are **not sharding items**. I checked
before filing them: `assign_finalizer_deterministic` (`finalizing.rs:163`) fetches its
salt through the same broken helper on the ordinary single-shard path, and
`request_single_finalizer` is called from `finalizing.rs:128` today. Both run in the
configuration that ships. So they became **Phase 0**, ahead of ingress, because Phases 1
and 2 are made of measurements and both defects make those measurements lie — one by
removing a security-relevant seed, one by reporting success for sends that never
happened.

Phase 7 got the opposite treatment: real gates, because the temptation here is unusual.
The sharding code is *close* — implemented, unit-tested, one call site away. But
`StakeSet::to_executor_set()` is `stakers.clone()`, so shards are sampled per
transaction from the entire validator set, which means a staked node lands in
effectively every shard over time and needs the union of their peers. **Density does not
fall.** Making it fall requires disjoint committee membership — a staking and consensus
change — so "sharding solves the mesh" is false as the code stands, and the phase needs
a written answer to that before opening.

Three corrections to the roadmap itself, all from checking rather than remembering:

- Phase 2 asked for **a collector**. That requirement is gone — nodes sign their own
  fragments, the log shipper moves them, the probe aggregates, and `directory_observer`
  means the probe needs no stake. The first concrete action is cheaper than it read.
- Phase 2 treated relay as a lever to pull. `TransportEngine` is constructed by nothing
  and `rns-net`'s `Transport` is a serial pipe, so the real choice is fewer validators,
  denser packing, or an application-layer gateway.
- Phase 2's exit test only asked whether the mesh formed. It now asks for four resource
  numbers, because we still have not established whether the mesh is socket-bound or
  O(N²)-verification-bound — and gateways only help the first one.

Two things deliberately unchanged: ingress still precedes every capacity claim, and
Phase 3 (durable stake) still gates any restart test — a fleet that forgets its
validator set cannot be meaningfully sharded either.

Also flagged as Phase 4 hygiene: `shard_quorum_percentage` is parsed, validated, read by
nobody, and its doc comment claims otherwise. A knob that silently does nothing is worse
than a missing one, because the operator who sets it believes something is true.

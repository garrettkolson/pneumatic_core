Phase 9 of the executor contract-execution plan (Model X cross-contract calls, ADR-016)
landed 2026-09-30. A contract on token A invokes a contract on token B via
`Call(target_token, entry_point, payload, snapshot_ref)`: the executor resolves B's state
pinned at the ref through the new `TargetStateProvider` (fail-closed on any miss), and runs
B's engine in the same call frame under a sub-gas budget (`A_remaining - CALL_BASE`,
`MAX_CALL_DEPTH = 8`; A charges `CALL_BASE + B.gas_used`). B's pinned state rides in
`ExecutionInput.call_ctx` (`Option<Arc<CallContext>>`), excluded from `canonical_bytes()`
like `storage`, so no existing `result_hash` changes. Surfaces: `SpecEngine` `Op::Call`
(status 1/0 on the stack) and the WasmEngine W4 `env.call` host import (result length, 0 on
any failure — never traps); both share the `execute_call` core in the new
`pneumatic_core::contracts::call` module. B's side is a cross-referenced commitment
(`H(A_tx_id || A_result_hash || snapshot_ref)`, domain `PNEUMATIC/XCALL/COMMIT/v1`) settled
at commit on B's chain — A's finality stays independent (no two-phase atomic commit).
Executor wiring: private `ExecutorTargetProvider` + `call_ctx` built in `execute_contract`.
Tests: 13 core call + 2 Wasm→Wasm round-trip (hand-assembled 578-byte `wasm_caller.wasm` —
required the `sleb_force2` workaround for the wasmparser 0.239.0 `read_var_i32` const-decode
bug, now recorded as `fact-wasmparser-read-var-i32-bug`) + 7 executor (6 provider
fail-closed + 1 full wiring). Core 639 → 654; executor 24 → 31; workspace `cargo test`
green (0 failed). Created `decision-cross-contract-calls` (ADR-016) and
`fact-wasmparser-read-var-i32-bug`, marked `task-executor-contract-execution` P9 ✅
(remaining: P10 e2e), bumped `decision-wasm-engine-tier2` W4 to landed, and synced
`_system/INDEX.md` (104 → 106 nodes).

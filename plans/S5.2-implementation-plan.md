# Phase S5.2: Finalizer Signs the Public Outputs

> Parent item: `pneumatic-shielded-implementation-plan.md` lines ~760–805 — "Finalizer: sign the public outputs (vote + block)".
> Preceding phase: S5.1 (shielded pool view + finalizer vote stubs). **S5.1's "Consumes this" is the contract here**: `SignShielded` body is the canonical bytes of `ShieldedTransaction`; the finalizer signs `stx.hash()` over those bytes; step 2 is the *same* `validate_shielded` call re-run against the finalizer's own view via `ShieldedPoolView`.

## Decisions (scope boundary)

- Vote reuses the existing `TransactionSignature` shape (all fields pre-existing). **No wire shape change.**
- Stake-weighted quorum, exact-integer `u128` (Phase 6.9 pattern). **No optimistic fast path** — the `signature_count == 1` branch in `try_finalize_optimistic` does not apply to shielded txs (they live in S5.1's parallel `shielded_transactions` map, not the pending registry).
- Votes bind the **pre** root (`stx.merkle_root`, the referenced root); the post-commit root is computed at S5.3 append time.
- **No** `ShieldedPool`/persistence (S5.3), no composite swap (S5.4), no committer changes (S5.3).
- Verified in-tree (impl-time check from parent plan): the non-empty `executor_sigs` requirement lives only in `ExecutedBlockValidatorSpec` (`src/validation.rs:264`); `SelfSignedBlockValidatorSpec` (`:128`) does not check it — so a shielded block with an S3.1 placeholder `Transaction` passes the SelfSigned block spec. No core change needed.
- Verified in-tree: node-server already routes `SignShielded`/`ShieldedVote` to the finalizer plugin's stub handlers (`node-server/src/node_server.rs:679–691`) and already passes `shielded_pool_view: Arc<dyn ShieldedPoolView>` into finalizer construction (`:375`, `:510`) — built at `:313–318` from `env_data.shielded_root_recency`. S5.2 threads that `Arc` into the `Finalizer` struct.
- Fail-closed everywhere: duplicate vote, unknown action, unregistered voter, unverifiable proof → no vote, no state mutation.

## Deliverables

### 1. `Finalizer` takes the pool view
- `finalizer/src/finalizer.rs:51`: add `pool_view: Arc<dyn ShieldedPoolView>` to `Finalizer` + `new` signature.
- `node-server/src/node_server.rs`: at the finalizer construction sites (`:375`, `:510`), pass the existing `shielded_pool_view` through. Update all in-tree `Finalizer::new` call sites (finalizer tests, node-server tests).
- Wire-compat: n/a (struct only).

### 2. Real `handle_sign_shielded` (finalizer plugin)
Replace the S3.2 stub:
1. Envelope auth: `authenticate_signature_message` analogue requiring **`NodeRegistryType::Finalizer`** (not Executor) — C1 pattern, envelope signature verified via `node_registry.find_node_types_by_public_key`.
2. Deserialize body as `ShieldedTransaction` from canonical bytes (`rmp`); decode failure → reject, no vote.
3. Re-run `validate_shielded` against the finalizer's **own** `pool_view` (`validate_shielded(spec, stx, ShieldedValidationDeps { spent, roots, recency_window } from the view)`) — advisory availability check, not a consensus gate. Any failure → no vote.
4. Sign `stx.hash()` (over the canonical bytes) → `TransactionSignature { transaction_id: stx.id, transaction_hash, signature, current_stake: self.current_stake_for_voter(key) }` — stake from epoch snapshot, never self-reported.
5. Send `Message::signed("ShieldedVote", …)` to finalizer peers + ack.

### 3. Real `handle_shielded_vote` (collector)
1. Same Finalizer-role C1 auth; verify the inner signature over `transaction_hash`.
2. Duplicate vote (key already present) → reject, no mutation (fail-closed, idempotent).
3. Add to a shielded signature collector (`signature_collector` analogue keyed on the shielded tx id).
4. `check_quorum` — stake-weighted, exact-integer `u128` over `stake_set`; **no optimistic branch**.
5. Quorum met → `try_finalize_shielded`.

### 4. `try_finalize_shielded` (new; `try_finalize` is uncalled in-tree — this is a new shielded tail, not a call into it)
1. `reconcile_signatures` over the collected votes.
2. **New** `build_signed_transaction_shielded` in `finalizer/src/block_builder.rs`: S3.1 `placeholder_transaction()` + `shielded: Some(stx)` + votes in `executor_sigs` (keyed by voting finalizer pubkeys). Keep exactly one additive schema field (`shielded`).
3. `sign_finalizer_block` — **unchanged** formula (`rmp(signed_tx)` already covers `shielded`).
4. `create_block` → `Message::signed("TransactionCommit", …)` → `send_to_committers` + `send_block_finalized` (sentinels get the pre-check notification via the existing S5.1 path).

## Decisions

1. **One load, one pool, per process** (already true post-S5.3: `build_runtime` loads once at :309 and shares the Arc). S5.4 adds no second load. Note the S5.3 API is `ShieldedPool::load(provider: &dyn DataProvider, partition_id: &str, recency: usize)` — the partition comes from the environment spec, and the standalone committer main (`committer/src/main.rs`) loads in `main` **before** `Committer::new` (the pool is a `Committer::new` parameter, not loaded inside it).
2. **The swap is the view composition (S5.3 contract) — with a live-view design caveat.** `ShieldedPool: ShieldedPoolView` landed in S5.3 (shielded_pool.rs:477: `nullifier_set()` → `&*self.nullifiers` — LIVE; `root_history()` → `&*self.view_roots` — a **stable boot-time snapshot**). The one-liner swap `let shielded_pool_view: Arc<dyn ShieldedPoolView> = Arc::clone(&shielded_pool);` therefore compiles and satisfies the trait, but the root side of the view is the boot snapshot: in safe Rust a `&'self dyn`-returning method cannot point at the guard's changing `Arc<MerkleRootState>` (no lock-free swap exists; crossbeam-epoch deliberately not added in S5.3). **So "one-line swap" in the S5.3 plan is infeasible as a pure drop-in if the sentinel/finalizer are to observe live roots** — S5.4 must first decide the live-view mechanism (options: (a) accept the boot snapshot for the role views and document it, keeping the one-liner; (b) an owned-snapshot view wrapper that reads `view_parts()`-style fresh state under the guard on each call; (c) a lock-free root-history reader). The nullifier side is live under every option. Sentinel/finalizer constructors are **untouched** — the trait is stable (sentinel.rs:52, finalizer.rs:96).
3. **Boot fail-closed** (inherited from S5.3 boot decision): corrupt envelope / root-integrity mismatch → boot error; true `NotFound` → S5.3's pristine-genesis seed + persist. The composite never "starts empty" silently.
4. **No transport special-casing.** Shielded payloads are ordinary length-prefixed frames (~4.6 KB typical for a 2-in/2-out transfer with PQC-hybrid note ciphertexts — well under the 16 MiB cap, wire protocol) — `route_data_plane` and `RnsNetwork` are unchanged.
5. **Wire-compat (ground rule 4).** No new action strings, no message/payload/field changes: sentinel `Verify`, finalizer `SignShielded`/`ShieldedVote` (already in the S5.2 action set), committer `Commit`/`BlockFinalized` — all as-is.

### 4. Tests
1. **Composite e2e**: the composite node (all roles installed) routes a shielded tx end-to-end in the in-process pipeline test — Sentinel `Verify` → Finalizer `SignShielded`/`ShieldedVote` → Committer `Commit`; assert the **shared** pool's root advances, nullifiers marked, and all three roles observed the same `Arc` (single-pool invariant).
2. **Fail-closed regression**: a role receiving an action outside its set → `RoleDispatcher` rejects `UnknownAction` (existing tests preserved, now with the real pool in the bundle).
3. **Discriminator** (parent plan :938–941): a test build with `"SignShielded"` removed from `FINALIZER_ACTIONS` → vote requests rejected `UnknownAction` by the dispatcher — proves the action-set gate is load-bearing, not decoration.
4. **Epoch check** (parent plan :895–903, "roadmap S5.4"): a shielded block loses a tip conflict through the composite's `resolve_block_conflict()` → pool unwinds in lockstep with `blockchain.remove_block()`: loser's commitments gone from the tree, loser's nullifiers unmarked, winner's update intact, `current_root() == tree.root()`. (Committer-level version is S5.3 verify item 7; this runs it through the composite dispatcher + conflict machinery, confirming the machinery itself needs no epoch-logic changes.)

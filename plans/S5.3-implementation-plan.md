# Phase S5.3: Committer Pool State Persistence + Nullifier Commit

> Parent item: `pneumatic-shielded-implementation-plan.md` lines 807–903 — "Committer: pool state persistence + nullifier commit".
> Preceding phase: S5.2 (finalizer signs the public outputs). **S5.2's contract is the input here**: a shielded commit arrives as an ordinary `TransactionCommit` whose block carries `signed_trans.shielded: Some(stx)` + the finalizer votes in `executor_sigs`; the block hash and finalizer sig already bind the exact nullifiers/commitments (S3.1). The committer is the final, authoritative consensus gate — sentinel pre-check (S5.1) and finalizer votes (S5.2) are availability/advisory, not soundness.

## Decisions (scope boundary)

- **Pool home + single-writer guard** (verified): the pool is ONE global committer structure in the committer crate (`committer/src/shielded_pool.rs`). Layout: `nullifiers: Arc<NullifierRegistry>` (S4.2, interior-mutable `&self` ops — shared with the view as-is), plus a `std::sync::Mutex` guard holding the `IncrementalMerkleTree` (S1.6) and the applied-update map. `MerkleRootState` (S4.3, `push` takes `&mut`) is published as an **immutable `Arc` snapshot**: the writer stages a copy, pushes, and swaps the `Arc` in under the guard; it never mutates a published `Arc` in place, so the view's returned references stay valid and no lock is held across reads. One guard, no concurrent root advances (Phase 5.4 single-epoch-writer pattern).
- **`ShieldedPool` implements `ShieldedPoolView`** (pool_view.rs:19–24 swap contract) — `nullifier_set()` → `&*self.nullifiers`, `root_history()` → `&**self.roots`.
- **Apply = authoritative re-check, reusing S4.1** (verified): steps 0–3 run the existing `ShieldedValidationSpec::validate_shielded` (validation.rs:547) with `ShieldedValidationDeps` built from the pool's **own** state (spent = pool nullifiers, roots = pool root history, window = `env_data.shielded_root_recency`, environment.rs:164, default 10). That covers proof re-verify via the shared `Lazy<ShieldedVerifier>` (validation.rs:436 — no new verifier) and the K-recency window. Step 4 (under the guard): idempotent no-op if `block.current_hash` is in the applied map → `mark_many_atomic` (registry.rs:456, all-or-nothing) → append `stx.commitments` as leaves (re-derived `poseidon_hash([x,y])`, transactions.rs:358) → `roots.push(post_root)` → record delta.
- **Rollback requires one new inverse API** (parent plan lines 866–873 mandates it; the UTXO semantics note applies): (a) `NullifierRegistry::unmark_many(&[[u8;32]])` — a **scoped, documented exception** to S4.2's "no removal API": callable only from the pool's single-writer rollback path, and only with the exact keys recorded in the losing block's applied delta. S4.2's type doc, AUDIT_CHECKLIST entry, and vault node (`decision-global-shielded-pool`, `concept-shielded-pool`) get updated in the same commit. (b) The tree has **no restore API** (verified: tree.rs exposes only `append`/`snapshot`) — add `IncrementalMerkleTree::from_leaves(&[Fp])` (re-appends; asserts the count). Rollback = drop the loser delta, truncate the leaf sequence, rebuild the tree, rebuild the root history (a derived, bounded view per roots.rs:64–68), assert `current_root() == tree.root()` (AUDIT_CHECKLIST.md:339 fail-closed check).
- **Persistence — Phase 5.4 pattern** (verified at data.rs:401–467): new `ShieldedPoolState { root, leaf_count, leaves (ordered Fp bytes), nullifiers, applied deltas (ordered, each with post_root) }` + `ShieldedPoolStateEnvelope { payload, hash }` (SHA-256 of canonical rmp bytes, `verify()` on load, surfaced — not swallowed). New **additive** `GetOp::ShieldedPool` / `SaveOp::ShieldedPool(envelope)` variants (ground rule 4: additive; old data services seeing an unknown tag fail closed). New abstract `DataProvider::get_shielded_pool` / `save_shielded_pool`; **6 impl sites** update: `DefaultDataProvider` (real, envelope-verified) + the 5 test stubs (committer/tests/helpers.rs:94, pipeline_integration.rs:66, stake_index.rs:269/302/342 — in-memory). **Rollout note:** the local data service must understand the new ops (or tolerate unknowns) before a shielded-enabled committer boots; rejection → fail-closed boot, the safe direction.
- **Commit-path ordering** (durability, roadmap 2.5): in `check_and_commit_transaction_results` (committing.rs:48), after the H12 extension and conflict resolution, under the pool guard: **revert** the loser's delta (if it had a shielded update; `CommitWinnerAfterRollback` arm, committing.rs:118) → **apply** the incoming block's delta **and persist** it (durable nullifiers **before** the block is reported committed) → `block_services.commit_block` (chain append) → on append failure, **revert** the just-applied delta (exact inverse). A node that reports commit has the nullifiers durably written — no crash-and-restart un-spend window.
- **Boot**: `Committer::new` loads the pool. Envelope mismatch / root-integrity mismatch → fail-closed **boot error** (Phase 6.5 spec-load behavior); missing key (true `NotFound`, distinguished from corruption) → seed the **pristine genesis state** (zero tree, empty nullifiers, genesis root at height 0 — the state of a chain with zero shielded history) and persist it. "Never start empty" means never silently forgetting prior spends; genesis is not that.
- **Hook sites** (verified, post d25f1ba modularization): commit path — `commit_block` call sites committing.rs:116/119, `block_services.commit_block` (block_services.rs:67–106); BlockFinalized path — `handle_block_finalized` (finalizing.rs:40), the `for committed_block in &committed` loop at finalizing.rs:103 (original append **and** orphan-promoted blocks) apply there, idempotently, before distribution.
- **H12 extension** (committing.rs:106): alongside the existing `transaction.hash()` match, a shielded commit additionally hash-matches wire `signed_trans.shielded` against `pending_registry.get_shielded(&tx_id)` (registry.rs:143, S5.1's never-evicted map) → same `TransactionPayloadMismatch`.
- **Scope boundary with S5.4**: S5.3 threads the real pool into the **committer plugin only** (standalone `committer` main + `node-server build_runtime`: construct `Arc<ShieldedPool>` at the build_runtime DI site, node_server.rs:310–311, and pass it into `Committer`/`BlockServices`). Sentinel/finalizer keep receiving a `SimpleShieldedPoolView` — but now built with `SimpleShieldedPoolView::with` (pool_view.rs:80) over the pool's **real** `Arc` parts (accessor `pool.view_parts()`), which is strictly better than today's pristine placeholder. S5.4 is then the one-line swap to `pool.clone()` as the view.
- **Wire-compat (ground rule 4)**: additive `DataOp` variants only. No new action strings, no message/payload changes, no `SignedTransaction`/`ShieldedTransaction` field changes — the committer's `Commit`/`BlockFinalized` actions are unchanged (S5.4 confirms `COMMITTER_ACTIONS` stays as-is).

## Deliverables

### 1. `ShieldedPool` — `committer/src/shielded_pool.rs` (new)
- Struct per Decisions (guard + shared `Arc`s); `new(recency_window)` (pristine genesis), `load(&dyn DataProvider)` (envelope-verify → rebuild tree via `from_leaves` → integrity assert → rebuild root history), `save(&dyn DataProvider)`.
- `apply_update(&Block) -> Result<(), CommitterError>` — steps 0–4 in order; no-op `Ok` when the block has no `shielded` field; idempotent when already applied.
- `revert_update(block_hash) -> Result<(), CommitterError>` — the exact inverse (delta lookup → `unmark_many` + leaf truncation + tree/root-history rebuild + integrity assert); missing delta is an error, never a silent skip.
- `impl ShieldedPoolView for ShieldedPool`; `view_parts()` accessor; integrity check `current_root() == tree.root()`.

### 2. Core additive APIs
- `src/shielded/tree.rs`: `IncrementalMerkleTree::from_leaves` (restore constructor; O(n·depth) re-append — fine at v1 scale, 32 B/leaf is already audited).
- `src/registry.rs`: `NullifierRegistry::unmark_many` + type-doc carve-out (rollback-scoped inverse); AUDIT_CHECKLIST S4.2 note updated in the same commit.

### 3. Persistence — `src/data.rs`
- `ShieldedPoolState` (serde, canonical bytes → `fingerprint()`), `ShieldedPoolStateEnvelope` (mirrors `StakeSnapshotEnvelope`, data.rs:403), `GetOp::ShieldedPool`, `SaveOp::ShieldedPool`, abstract trait methods + `DefaultDataProvider` round-trip (verify-on-load, `SnapshotCorrupt`-class `DataError` on mismatch) + 5 test-stub impls.

### 4. Committer wiring
- `Committer` (committer.rs:96) and `BlockServices` (block_services.rs:26) gain `pool: Arc<ShieldedPool>`; update **all** `Committer::new`/`BlockServices::new` call sites (committer unit tests, `pipeline_integration.rs`, node-server `build_role_plugin`).
- H12 shielded extension (committing.rs:106); commit-path revert→apply→persist→append→revert-on-failure sequence (Decisions); BlockFinalized idempotent apply at finalizing.rs:103.
- `CommitterError` new variants: `ShieldedProofInvalid { tx_id, cause }`, `PoolState { kind: &'static str, cause }` (missing-vs-corrupt-vs-integrity at boot), `PoolPersist { cause }`, `PoolRollback { block }`. Step-2 double-spend stays `Core(PneumaticError::Validation([StaleNullifier]))` — the exact named error S6.2 asserts.

### 5. Boot load
- `Committer::new`: load → fail-closed on corrupt/integrity; seed+persist pristine genesis on true NotFound (Decisions).

### 6. Node-server threading (committer plugin only)
- `build_runtime` (node_server.rs:310–311 site): construct `Arc<ShieldedPool>` (load) into the DI bundle; sentinel/finalizer receive `SimpleShieldedPoolView::with(pool.view_parts())`; committer plugin receives the pool. S5.4 swaps the two view lines.

## Verify

After every item: `cargo check` + `cargo test --workspace` green. Discriminators (parent plan, lines 882–903):

1. **Commit → pool advances + persists**: root advances, nullifiers marked, state saved; **restart roundtrip**: reload → byte-identical pool state.
2. **H12 extension**: mutate wire `signed_trans.shielded` vs registry entry → `TransactionPayloadMismatch`, no apply.
3. **Idempotency**: apply the same block twice (Commit path, then BlockFinalized) → second is a no-op; root unchanged; each nullifier marked exactly once.
4. **Cross-block double-spend**: two distinct blocks (even different tokens) spending the same note → first commits, second rejected `StaleNullifier` (global first-spent-wins under the single guard).
5. **Authoritative re-check**: tx with a full finalizer quorum but an **invalid proof** → committer rejects the commit (soundness does not depend on trusting voters; the sentinel/finalizer verdicts are never relayed).
6. **Durability ordering**: test inverts the ordering (mark-after-report) and simulates crash-after-report → double-spend window opens; the real code is shown to close it (the test exists to PROVE the ordering matters).
7. **Rollback lockstep**: a shielded block loses a tip conflict (`CommitWinnerAfterRollback`) → loser's leaves gone from the tree, loser's nullifiers unmarked, winner's update intact, `current_root() == tree.root()`, all in lockstep with `blockchain.remove_block()` (blocks.rs:267) — the parent plan's epoch-check item (conflict machinery itself unchanged).
8. **Boot fail-closed**: corrupt envelope / root-integrity mismatch → boot error, no silent empty start.

Test-count progression: 821 (S5.2 close) → **833+** at S5.3 close (pool unit tests: apply/idempotency/double-spend/revert/rollforward; roundtrip + boot; the 8 committer-pipeline discriminators).

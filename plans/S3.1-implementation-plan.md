# Phase S3.1 — `ShieldedTransaction` Type: Implementation Plan

> Companion to `pneumatic-shielded-implementation-plan.md` (Phase S3.1). This
> document breaks that checklist entry into concrete, ordered implementation
> tasks, grounded in the *actual* code in `src/transactions.rs` and the S1.x
> primitives already in `src/shielded/`. It records the deviations from the
> plan's loose stub where the stub does not match the implemented types.

## 0. One-paragraph scope

S3.1 introduces the wire type that carries a shielded (Zcash-tier privacy) value
transfer through the pipeline and — critically — **binds that payload into the
block hash** so the shielded pool update becomes consensus-visible, replayable,
and rollback-atomic. Everything here lives in `src/transactions.rs`; the change
is strictly **additive** — the existing `Transaction` and `SignedTransaction`
wire shapes are left byte-identical (Ground Rule 4).

## 1. What is in / out of scope

**In scope (this item only):**
- The `ShieldedTransaction` struct and its canonical serialization + `hash()`.
- The single additive `shielded: Option<ShieldedTransaction>` field on
  `SignedTransaction` and the canonical `Transaction` carrier.
- `canonical_signed_trans_bytes` appending the canonical shielded bytes when
  `Some`, so the block hash binds (nullifiers, commitments, referenced root,
  proof, ciphertexts).
- The deterministic placeholder `Transaction` a shielded block carries in
  `SignedTransaction.transaction`.
- Regression guard: non-shielded byte sequences are unchanged.

**Explicitly NOT in scope (other S3 items):**
- **S3.2** — message-action wiring (`"ShieldedTransfer"`, `"SignShielded"`,
  `"ShieldedVote"`). S3.1 defines the *type*; S3.2 wires the *action strings*.
- **S3.3** — the `pneumatic_prover` crate (client-side proving / key model).
- **S4.x** — `ShieldedValidationSpec`, nullifier set, root freshness.
- **S5.x** — pipeline routing, finalizer voting, committer pool persistence.
- **S1.x** — the primitives `ShieldedTransaction` references (`commit`,
  `nullifier`, `root_to_bytes`, note encryption). They are already DONE.

## 2. Dependencies & sequencing

- **Depends on (DONE):** S1.3 `commit()`, S1.4 `nullifier()`, S1.6
  `root_to_bytes`/`bytes_to_root`/`IncrementalMerkleTree`, S1.5 note encryption.
  S3.1 consumes only their **byte outputs**, so it does not even need to
  `use crate::shielded` — `ShieldedTransaction` is a pure wire type.
- **Feeds S3.2** (`hash()` is the digest finalizers sign; the struct is the
  inner message body), **S5.2** (finalizer signs `ShieldedTransaction::hash()`),
  **S5.3** (H12 hash-match of the wire `signed_trans.shielded`).
- **Sequencing:** S3.1 runs in parallel with S2 (types don't need the circuit).
  It must complete before S3.2/S5.2/S5.3.

## 3. Ground-truth API surface (corrects the plan stub)

The plan stub wrote `commitments: Vec<Fr-as-[u8;32]>`. The implemented S1.x
primitives use the **Pallas base field `Fp`** and an **affine curve point** —
not a bare `Fr`. The wire fields are all byte encodings produced by the S1.x
functions:

| `ShieldedTransaction` field | Wire type | Source / encoding (S1.x) |
|---|---|---|
| `id` | `String` | uuid, mirrors `Transaction` |
| `action` | `String` | constant `"ShieldedTransfer"` |
| `token_id` | `Vec<u8>` | the self-signed token |
| `nullifiers` | `Vec<[u8;32]>` | `note::nullifier(&note, &spend_key) -> [u8;32]` |
| `commitments` | `Vec<[u8;32]>` | `note::commit(&note).to_bytes()` — **32-byte *compressed affine point***, not a raw `Fp`. The committer re-derives the tree leaf as `poseidon_hash([x,y])` at append time (S5.3) |
| `merkle_root` | `[u8;32]` | `tree::root_to_bytes(&root) -> [u8;32]` (little-endian) |
| `proof` | `Vec<u8>` | Halo2 proof bytes (S2.1) |
| `note_ciphertexts` | `Vec<Vec<u8>>` | `encrypt_note`/`encrypt_note_to_two` output (~2.3 KB each, PQC-hybrid) |
| `fee` | `u64` | public; 0 for v1 |

**Consequences this must respect:**
- `commitments` round-trip as compressed points: wire `bytes` ⇔ `EpAffine::from_bytes`
  at the committer, then `tree.append(&point)`. The wire type is bytes; the
  `shielded` module is not needed by `transactions.rs`.
- `[u8;32]` is already serde-serializable in this crate (used by
  `MembershipProof` / `TreeState`), so `#[derive(Serialize, Deserialize)]` on
  `ShieldedTransaction` compiles as-is.

## 4. Wire-compat guarantees (Ground Rule 4 — must hold, proven by tests)

1. **Non-shielded is byte-identical.** For every existing (non-shielded) block,
   the MsgPack `rmp(SignedTransaction)`, the canonical `canonical_signed_trans_bytes`,
   and every derived block hash are **byte-for-byte identical** to today.
   Achieved by `#[serde(default, skip_serializing_if = "Option::is_none")]` on the
   new field (serde drops it when `None`) plus an append path that only runs when
   `Some`.
2. **Additive field, no reshaping.** `Transaction` is untouched; only
   `SignedTransaction` gains one optional field.
3. **Old nodes stay safe.** A pre-upgrade node decoding a shielded block sees an
   extra unknown map key (serde default = ignore) — but it cannot *produce* a
   shielded block, and the unknown action fails closed (S3.2), so the whole
   shielded tx is rejected upstream. No upgrade dance required.

## 5. Implementation tasks

All changes are in `src/transactions.rs`. Implement in order; each task is
self-checking with `cargo check`.

### Task A — `ShieldedTransaction` struct

Add after the `Transaction` struct (before `Bid`, or grouped with the transaction
models). `#[derive(Serialize, Deserialize, Debug, Clone)]`. All fields are wire
primitives — **no `use crate::shielded` needed**:

```rust
/// A shielded (Zcash-tier privacy) value transfer.
///
/// The network confirms validity (correct spend authority, no double-spend,
/// value balance) via the Halo2 proof + nullifiers + commitments, without any
/// node ever observing sender, receiver, or amount. Every field is a wire
/// primitive, so this type is self-contained and carries no note openings,
/// spend keys, or the internal `shielded` module on the wire. See
/// `pneumatic-shielded-implementation-plan.md` (Phase S3.1).
#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct ShieldedTransaction {
    /// Unique tx id (uuid, mirroring `Transaction`).
    pub id: String,
    /// Always `"ShieldedTransfer"` — the inner action string defined in S3.2.
    pub action: String,
    /// The self-signed token being transferred. The global pool is
    /// token-agnostic, but the tx is still filed against one shielded-opt-in token.
    pub token_id: Vec<u8>,
    /// Nullifiers of the spent notes (`note::nullifier`, S1.4). Pairwise
    /// distinct within the tx; their uniqueness is the double-spend defense (S4.2).
    pub nullifiers: Vec<[u8; 32]>,
    /// New notes — one per output. Each is a 32-byte **compressed affine point**
    /// (`note::commit(&note).to_bytes()`, S1.3). The committer re-derives the
    /// tree leaf (`poseidon_hash([x, y])`) from these at append time (S5.3).
    pub commitments: Vec<[u8; 32]>,
    /// Referenced pool root — the Merkle root the proof was proved against.
    /// 32-byte little-endian (`tree::root_to_bytes`, S1.6).
    pub merkle_root: [u8; 32],
    /// Halo2 proof bytes (`ActionCircuit` proof, S2.1).
    pub proof: Vec<u8>,
    /// Encrypted note ciphertexts, one per output. Each ~2.3 KB PQC-hybrid
    /// payload encrypted to a recipient + viewing key (S1.5).
    pub note_ciphertexts: Vec<Vec<u8>>,
    /// Public fee; `0` for v1.
    pub fee: u64,
}
```

### Task B — canonical bytes + `hash()`

Mirrors `Transaction::canonical_signature_bytes` / `Transaction::hash`. Because
`ShieldedTransaction` contains **no `HashMap`** (only fixed-order `Vec`s and
primitives), its serde form is already canonical — stable across a round-trip and
independent of insertion order. No separate `CanonicalShieldedTransaction` struct
is required (contrast with `CanonicalSignedTransaction`, whose `executor_sigs`
`HashMap` forces one):

```rust
impl ShieldedTransaction {
    /// Deterministic serialization: the binding surface the finalizer signs and
    /// the committer hash-matches. `ShieldedTransaction` has no `HashMap`, so the
    /// serde form is already canonical (round-trip stable, order-independent) — the
    /// same property `Transaction::hash` relies on.
    pub fn canonical_bytes(&self) -> Result<Vec<u8>, PneumaticError> {
        crate::encoding::serialize_to_bytes_rmp(self)
            .map_err(|e| PneumaticError::Encoding(e.to_string()))
    }

    /// SHA-256 over the entire payload. Mirrors `Transaction::hash`: finalizers
    /// sign this digest (S5.2) and the committer hash-matches the wire form against
    /// its validated registry entry (S5.3, H12 extension). Covers every field — a
    /// swap of any field is caught.
    pub fn hash(&self) -> Result<Vec<u8>, PneumaticError> {
        let bytes = self.canonical_bytes()?;
        Ok(BasicHashProvider::new().hash(&bytes))
    }
}
```

### Task C — additive `shielded` field on `SignedTransaction`

Add the field to the existing `SignedTransaction` struct (transactions.rs:263) with
`serde(default, skip_serializing_if)` so it is absent for every non-shielded block:

```rust
    /// Shielded (privacy-preserving) value transfer carried in this block.
    ///
    /// `None` for every ordinary block — the field is additive, so the MsgPack
    /// form and every existing canonical byte sequence stay byte-identical to
    /// today for non-shielded blocks (Ground Rule 4). When `Some`, the pool
    /// update is bound into the block hash via `canonical_signed_trans_bytes`
    /// (see Task D). `#[serde(default)]` lets a pre-upgrade node ignore the new
    /// key on a shielded block; such a block is still rejected upstream by the
    /// unknown-action gate (S3.2).
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub shielded: Option<ShieldedTransaction>,
```

**Also update `SignedTransaction::test_transaction()`** (transactions.rs:290) to
set `shielded: None` — this is a required existing-helper update (Ground Rule 3);
without it the struct no longer compiles at its call sites.

### Task D — `canonical_signed_trans_bytes` appends the canonical shielded bytes

Current function (transactions.rs:353-372) serializes a `CanonicalSignedTransaction`
(the 10-field canonical view). **Append** the shielded bytes *after* the core
serialization when `Some`. Core struct unchanged → non-shielded output is
byte-identical by construction:

```rust
pub(crate) fn canonical_signed_trans_bytes(
    tx: &SignedTransaction,
) -> Result<Vec<u8>, std::io::Error> {
    let cst = CanonicalSignedTransaction {
        transaction_id: &tx.transaction_id,
        transaction: &tx.transaction,
        total_stake: tx.total_stake,
        total_voters: tx.total_voters,
        leader_address: &tx.leader_address,
        leader_stake: tx.leader_stake,
        leader_hash: &tx.leader_hash,
        finalizer_addr: &tx.finalizer_addr,
        finalizer_sig: &tx.finalizer_sig,
        executor_sigs: tx.executor_sigs.iter().collect(),
        proposer_key: &tx.proposer_key,
    };
    let mut bytes = crate::encoding::serialize_to_bytes_rmp(&cst)?;

    // Consensus-binding: append the canonical shielded bytes when present so the
    // block hash uniquely binds (nullifiers, commitments, referenced root, proof,
    // ciphertexts). Absent for non-shielded blocks → byte-identical to today.
    if let Some(shielded) = &tx.shielded {
        let shielded_bytes = shielded
            .canonical_bytes()
            .map_err(|e| std::io::Error::new(std::io::ErrorKind::Other, format!("shielded canonical: {e}")))?;
        bytes.extend_from_slice(&shielded_bytes);
    }
    Ok(bytes)
}
```

> **Design note — append (recommended) vs. inline.** The above is **Approach B**:
> the core canonical struct is byte-for-byte unchanged and the shielded bytes are a
> clearly-delimited suffix. This matches the plan's exact wording ("appends the
> canonical shielded bytes when `Some`") and makes the byte-identical guarantee
> obvious. An equivalent **Approach A** adds
> `#[serde(default, skip_serializing_if = "Option::is_none")] shielded: Option<&'a ShieldedTransaction>`
> directly to `CanonicalSignedTransaction` — serde drops it when `None` (identical
> non-shielded bytes) and serializes it inline when `Some`. Both are
> consensus-correct; Approach B is recommended here for the explicit append.

### Task E — deterministic placeholder `Transaction`

A shielded block's `SignedTransaction.transaction` cannot hold a real
`Transaction` (there is no sender/nonce/amount/nonce — the sender identity is
hidden). It carries a **deterministic placeholder** so the block hash binds a
fixed carrier alongside the `shielded` field:

```rust
impl ShieldedTransaction {
    /// The deterministic placeholder `Transaction` a shielded block carries in
    /// `SignedTransaction.transaction`. Real `Transaction` fields (sender,
    /// amount, nonce) do not exist for shielded transfers — the pool update is
    /// consensus-bound via the `shielded` field instead. Deterministic so the
    /// block hash is a pure function of the shielded tx (never of placeholder
    /// garbage).
    pub fn placeholder_transaction(&self) -> Transaction {
        Transaction {
            id: self.id.clone(),
            action: "ShieldedTransfer".to_string(),
            token_id: self.token_id.clone(),
            bid: None,
            sequence_number: 0,
            sender: vec![],
            receiver: vec![],
            amount: None,
            timestamp: 0,
            result_hash: vec![],
            sender_signature: vec![],
        }
    }
}
```

The finalizer (S5.2) builds the shielded `SignedTransaction` as:
`transaction = shielded.placeholder_transaction()`, `shielded = Some(shielded)`,
plus the collected votes in `executor_sigs`.

## 6. Discriminator tests (one per requirement; each fails without its change)

Add to the `#[cfg(test)]` module at the end of `src/transactions.rs`. Per the
AUDIT_CHECKLIST ground rules, each is proven by temporarily reverting the
corresponding code and watching it fail.

1. **`shielded_serde_roundtrip_byte_identical`** — serialize a representative
   `ShieldedTransaction` (non-empty `nullifiers`, `commitments`, a `merkle_root`,
   `proof`, and `note_ciphertexts`) via `serialize_to_bytes_rmp`; deserialize;
   re-serialize. `A == B`. Proves the canonical form is round-trip stable.
2. **`shielded_hash_stable_across_roundtrip`** — `tx.hash() == tx_roundtrip.hash()`.
   The digest the finalizer and committer both compute must agree after a wire
   round-trip.
3. **`shielded_hash_sensitivity_flip_nullifier`** (plan's *discriminator 2*) —
   flip one byte of `nullifiers[0]`; assert `hash()` and `canonical_bytes()` both
   change. Proves the digest binds the nullifiers (a double-spend-critical field).
4. **`shielded_hash_sensitivity_flip_merkle_root`** — flip one byte of
   `merkle_root`; assert `hash()` changes. Proves the referenced root is bound.
5. **`non_shielded_canonical_bytes_match_baseline`** (regression — Ground Rule 4) —
   hardcode the current `canonical_signed_trans_bytes(&SignedTransaction::test_transaction())`
   bytes as the expected baseline (capture once via a throwaway run *before* the
   change), then assert the post-change value equals it. Any accidental reshaping
   of the non-shielded canonical bytes fails this. The existing `blocks.rs` hash
   tests (unchanged) are the complementary guard.
6. **`non_shielded_msgpack_field_is_absent`** — build a `SignedTransaction` with
   `shielded: None`, MsgPack-serialize it, and assert the serialization has **no**
   `shielded` map key (i.e. equals a hand-built serialization without the field),
   proving `skip_serializing_if` actually drops it.
7. **`shielded_block_hash_binds_shielded_field`** — build a `SignedTransaction`
   with `shielded: Some(tx)`; compute `canonical_signed_trans_bytes`; flip one
   byte of `tx.nullifiers`; assert the canonical bytes change. Proves the block
   hash carries the shielded payload.
8. **`placeholder_transaction_is_deterministic`** — `tx.placeholder_transaction()`
   built twice is `==`; and it copies `id`/`action`/`token_id` from the shielded tx
   with all other fields zeroed.

## 9. Risks & open points

- **`io::Error` vs `PneumaticError`.** `canonical_signed_trans_bytes` returns
  `std::io::Error`; the shielded canonical encode returns `PneumaticError::Encoding`.
  The one-line map in Task D is the only friction — keep it.
- **Commitment encoding.** `commitments` are compressed affine points
  (`EpAffine::to_bytes` ⇔ `EpAffine::from_bytes`). The committer (S5.3) must decode
  them back to `EpAffine` before `tree.append`. Get this right — a bad decode must
  fail closed (`bytes_to_root`-style `Option` → error), never silently truncate.
- **`ShieldedNote` is not serde-serializable** (carries `Fq`); ensure no task
  accidentally tries to derive `Serialize` on it. `ShieldedTransaction` must stay
  bytes-only.
- **Determinism of `hash()`.** Relies on `ShieldedTransaction` having no `HashMap`.
  If a future field is ever added as a map, a canonical view would be required.
  This is a documented invariant (see Task B doc comment).
